## Design

Two independent deliverables share the existing plan/replay architecture. Source boards must retain their mechanic symbols as editable objects, rather than misclassifying pictures as people or losing emoji coordinates. Assignment coverage must show whether actual recorded status streams reproduce authored branches, with separately qualified position observations and replayable examples. It never infers success from movement, enables a rule, widens a condition or guesses a status ID from an image.

Use native game artwork for recognized game icon assets and bundled, attributed, pinned Unicode emoji artwork for emoji. No arbitrary network URLs are fetched by the render loop. Unknown art retains a readable visible fallback and import diagnostics. Emoji clusters remain whole when drawn or truncated.

Use retained raw ReplayAttempt evidence, not bounded shareable summaries, for cross-recording analysis. Counts are recordings, not independent pulls: an imported FF Logs fight and a local recording may represent the same real pull. Identical FF Logs report/fight references count once. Status tests and positional proximity are separate results. Match encounter, actor scope, plan and board geometry before comparing; unsupported/gapped/short recordings remain unknown. Reuse the actual adaptive evaluator with structured branch attribution.

## Contracts and ownership

- Import/model owner: append `CanvasItemKind.Symbol = 8`. `CanvasItem.Emoji` stores a whole Unicode sequence; existing `IconId` stores game artwork ID; `Text` retains the source caption for editing/fallback. The bounded `SymbolAsset.Cut4` stores the remaining four-circle diagram. Symbol `Extent` is normalized half-width/half-height; `Rotation` and new `FlipX`/`FlipY` preserve transforms. Never bind a symbol to a roster seat. Clone, compact/disk/share serialization and validation must preserve it. Symbol plans require format 5; old share/replay readers reject them, but old disk readers cannot be fixed retroactively, so document backups and downgrade limits. Owner coordinates names with renderer.
- Renderer owner: `CanvasSymbols`/emoji resource helpers, arena symbol draw/hit-test, mini retention and cluster-safe labels, symbol editor controls. Use bounded cached textures, measured/drawn bounds from one geometry function, clear ownership and fallback. Own any resource entry needed in the csproj; tell root. Bundled artwork must have exact source/version/license attribution and no runtime download dependency.
- Evidence owner: pure `AdaptiveEvidenceAudit.Analyse(PlanDocument, AdaptiveMechanic, IReadOnlyList<ReplayAttempt>)`, structured results and examples, real evaluator branch identity, exact duplicate draft consolidation, and a compact Adaptive coverage UI with Review links. Cache or explicitly refresh outside combat rather than scan all recordings every frame. Exact condition/destination duplicates reuse candidates; conflicting destinations remain reviewable conflicts.
- Root: release confirmation, shared integration, CI entries, documentation, independent review, full build/regressions and deliverables. No agent commits or publishes.

## Evidence boundaries

Fresh Act 1 source uses emoji U+1F432 and game art 214336/214337; game icon IDs are not Status row IDs. All six currently linked Caro boards retain 195 positioned emoji, 344 native game-art icons and two Cut4 diagrams, with zero artwork fallbacks in this corpus. Source text boxes still become notes; custom backgrounds and some primitives retain the documented approximations. The six selected Idyllic tables now resolve safely through literal member access, recovering 21 guide slides. The full Caro composition with Ranged/group 1/default tether choices has 141 slides and 3,343 editable objects, including all 541 symbols, with no unresolved guide choices.

The licensed bundled emoji renderer covers board symbols and canvas/mini captions, not every ordinary ImGui text surface. Unsupported future Unicode sequences retain their source payload and a display fallback. Do not claim universal pixel-identical or complete executable-guide import based on fixing this corpus. Prefer preserving available authored data with explicit coverage over silently omitting it.
